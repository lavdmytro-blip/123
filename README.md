# BingX AI Signals — Telegram Mini App / Railway

Полноценный исходный проект технического анализа публичных котировок **BingX USDT-M Perpetual**. Интерфейс React/TypeScript + Lightweight Charts, сервер Python/FastAPI, Telegram-бот через защищённый webhook, SQLAlchemy/PostgreSQL, опциональный Redis, необязательный модуль AI-комментариев.

**Режим строго read-only:** приложение не выполняет заявки, не запрашивает BingX API keys, не подключает кошельки и не обещает прибыль. LONG/SHORT/WAIT — технические сценарии на основании завершённых свечей, а не предложение торговать. Применение сценариев к реальным сделкам может привести к потере средств.

## Что работает

- Поиск **всех** USDT-пар из публичного `/contracts`, живые цены и 24-часовое изменение, рыночный список; мини-графики по часовым свечам.
- Свечной график с масштабированием и EMA 20/50/200, объёмами, 7 таймфреймами, линиями ENTRY/SL/TP1–TP3.
- Детерминированные расчёты RSI(14), MACD(12/26/9), EMA, Bollinger(20,2), ATR(14), объёма, локальных экстремумов, уровней; funding/OI/depth как дополнительные сведения (если получены).
- **LONG / SHORT / WAIT** по прозрачным правилам. Вход, стоп и цели определяются структурой цены, ATR и заданным соотношением риска/результата; если результат не обоснован, WAIT и пустые уровни.
- Публичный BingX REST без торгового API-ключа, прямой публичный WebSocket `BTC-USDT@ticker` с GZIP/Ping/Pong/reconnect и REST fallback.
- Вход через Telegram WebApp `initData` с серверной HMAC-проверкой. Без Telegram доступны только просмотр цен и анализ, но не пользовательские данные.
- История, избранное, настройки, ценовые уведомления, слежение за новыми сигналами, уведомления о TP/SL через Telegram. Настройки и данные сохраняются в Postgres.
- 1m-свечи для контроля прохождения целей. Если TP/SL внутри одной свечи, статус **AMBIGUOUS**, если недостаёт истории, **STALE**. Никакой выдуманной статистики.
- Redis-кеширование при заданном `REDIS_URL`, кеш в памяти иначе; ограничение запросов на endpoint, обработка ошибок, таймауты, кеш и проверка свежести данных.
- Необязательные AI-комментарии: при указании `OPENAI_API_KEY` сервер отправляет уже готовые аргументы в AI для **словесной** интерпретации. Без ключа отображаются полноценные алгоритмические объяснения, но не выдается текст за работу LLM.

## Как развернуть на Railway (один веб-сервис)

1. Распакуйте ZIP. Создайте **приватный репозиторий GitHub** и загрузите **содержимое папки `bingx-ai-signals`** в корень репозитория (Dockerfile должен лежать в корне).
2. Создайте новый проект на **Railway → New Project → Deploy from GitHub Repo**, подключите репозиторий. Railway распознает корневой `Dockerfile` и будет собирать и фронтенд, и сервер в одном контейнере. **Не устанавливайте Root Directory на `/frontend` или `/backend`.**
3. Добавьте в проект Railway **PostgreSQL** (New → Database → PostgreSQL). В переменных вашего приложения задайте `DATABASE_URL` ссылкой на `DATABASE_URL` PostgreSQL-сервиса, например `${{Postgres.DATABASE_URL}}` (имя `Postgres` может отличаться). Не используйте SQLite на Railway для постоянной истории: локальные файлы контейнера могут исчезнуть при редеплое.
4. В Railway → ваш сервис → **Settings → Networking → Generate Domain** получите HTTPS-адрес вида `https://xxxxx.up.railway.app`.
5. В Telegram откройте **@BotFather**, создайте собственного бота через `/newbot`. Скопируйте выданный токен — никому его не пересылайте и не добавляйте в Git.
6. В Railway → ваш сервис → Variables добавьте:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | Токен от BotFather |
   | `PUBLIC_BASE_URL` | Ваш **точный HTTPS-адрес** Railway, без завершающего `/` |
   | `WEBHOOK_SECRET` | Случайная строка из `A-Z a-z 0-9 _ -`, минимум 32 символа |
   | `DATABASE_URL` | Railway reference на Postgres, например `${{Postgres.DATABASE_URL}}` |
   | `ENABLE_WORKER` | `true` |
   | `REDIS_URL` | *Необязательно*: reference URL Redis из Railway |
   | `OPENAI_API_KEY` | *Необязательно*: только для дополнительных AI-комментариев |
   | `OPENAI_MODEL` | *Необязательно*: `gpt-4.1-mini` (можно изменить на поддерживаемую модель) |

7. После сохранения Railway автоматически редеплоит проект. Дождитесь статуса **Success**. Если нужно, нажмите Redeploy. Перейдите на `https://ваш-домен/api/health` — ожидается `{"status":"ok", "mode":"read-only", "bot":true}`.
8. Откройте **своего** Telegram-бота и отправьте `/start`. Появится кнопка **«Открыть Mini App»**, а также кнопка в меню чата. Telegram не требует ручного указания Mini App URL в BotFather для этой web_app-кнопки: сервер устанавливает menu button через Bot API.
9. Если бот не отвечает, посмотрите **Railway → Deployments → View Logs**. Проверьте `BOT_TOKEN`, `PUBLIC_BASE_URL` и `WEBHOOK_SECRET`. Если сайт открывается, но нет цен — проверьте доступность публичного BingX API из выбранного региона Railway и сообщения об ошибке.

### Что важно в Railway

- Запускайте **ровно одну реплику** сервиса: встроенный фоновой обработчик отслеживает сигналы и отправляет уведомления. Для масштабирования перенесите `worker.loop` в отдельный сервис с распределённой блокировкой.
- Укажите `DATABASE_URL`, иначе используется SQLite только для локальной разработки; на Railway это непостоянный том контейнера.
- Redis необязателен: без него работает кеш внутри приложения; с ним кеш переживает вызовы между обработчиками.
- Для HTTPS ничего отдельно настраивать не требуется: публичный домен предоставляет Railway.
- Секреты — **только** Railway Variables; не записывайте их в frontend или .env в GitHub.
- Уведомления от бота возможны только если пользователь **начал диалог `/start`** и разрешил уведомления.

## Локальный запуск

В двух терминалах:

**Backend** (Python 3.12+):

```bash
cd backend
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
# BOT_TOKEN можно не задавать для гостевого анализа
uvicorn app.main:app --host 127.0.0.1 --port 8080 --reload
```

**Frontend** (Node.js 20+):

```bash
cd frontend
npm install
npm run dev
```

Откройте `http://localhost:5173`. Vite пересылает `/api` на FastAPI. В обычном браузере доступен гостевой режим; персональные функции требуют запуска внутри Telegram.

Проверить Python-часть:

```bash
cd backend
pytest -q
```

## Что делает аналитический алгоритм

- Для EMA 200 необходимо минимум **210 закрытых свечей**, для 1d это несколько месяцев исторических данных.
- Незавершённая последняя свеча **не участвует** в расчётах; устаревшая история отвергается.
- Веса: EMA trend 3, MACD momentum 2, RSI 1, объём 1, локальная структура 1. LONG/SHORT — минимум 6 баллов и минимум на 4 больше противоположной стороны; иначе WAIT.
- Стоп рассчитывается от локальной структуры и ATR, минимально 1.5 ATR; TP1/TP2/TP3 ориентируются на 1.5R, 2R, 3R. Если сопротивление/поддержка слишком близко, риск слишком велик или цены некорректны, результат WAIT.
- Funding, open interest, стакан служат контекстом. Они **не подменяют** исторические данные и не создают ложное ощущение точности.
- Сила сигнала 0–8 — **не** вероятность прибыли. Это лишь сумма голосов алгоритма.
- История подсчитывает подтверждённые TP1/TP2/TP3 и SL. Невозможность восстановить внутрисвечной порядок имеет отдельный статус.

**Ограничения текущей версии:** текст интерфейса преимущественно русский; настройка `EN` сохраняется, полноценная англоязычная локализация пока не реализована. Уведомления и проверка исходов выполняются фоновым циклом примерно каждые 90 секунд, обнаружение новых направлений — примерно каждые 6 минут, с лимитом `MAX_SCAN_WATCHES`. Проверка срабатываний использует минутные OHLC, не биржевой журнал сделок; если сервис долго не работает или история недоступна, исход может остаться непроверенным. Никакой полноценной AI-модели без отдельного ключа нет. Перед публичным запуском на большое число пользователей желательно добавить распределённую очередь задач, наблюдаемость и нагрузочное тестирование.

## API / источники

Используются **только публичные** конечные точки BingX (`contracts`, `ticker`, `klines`, `fundingRate`, `openInterest`, `depth`) и публичный USDT-M swap WebSocket. Документация BingX:

- https://github.com/BingX-API/api-ai-skills/blob/main/skills/swap-market/api-reference.md
- https://github.com/BingX-API/api-ai-skills/blob/main/skills/swap-ws-market/api-reference.md
- https://docs.railway.com/deployments/monorepo

## Безопасность

Проверка Telegram initData проводится на backend через HMAC и срок действия. Webhook проверяет секретный заголовок Telegram. База, уведомления, настройки и избранное требуют авторизованного пользователя. Нет торговых API методов, account endpoints, вывода средств или управления позициями. Приложение не должно использоваться как гарантия прибыльных сделок.
